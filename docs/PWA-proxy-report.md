# PWA 代理与前后端启动问题说明

## 背景
- 开发模式下 vite-plugin-pwa 的 Service Worker 会在加载时预取 `/api/...`。
- 如果 NestJS API 尚未启动或端口未监听，这些请求会被 Vite 代理到一个未就绪的目标，触发大量 `ECONNREFUSED`，造成 HMR 卡死。

## 现状
- 已在开发环境禁用 SW 预取：`devOptions.enabled: false`。
- 启动顺序由 `pnpm dev`（脚本 `scripts/dev.js`）强制改为：先起后端并通过 `/api/health` 检查，再起前端。

## 头像需求说明
- “发送后立即显示头像” 的优化在当前版本已以更安全的方式恢复：前端乐观消息会复用已知头像，但不触发额外网络请求；后端正常返回后自动替换为最新头像。
- 如再次出现代理雪崩，需优先检查后端健康与 SW 是否被错误启用，避免把头像逻辑误认为根因。
