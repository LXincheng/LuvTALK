# LuvTALK 上线与数据库接入审计

> 审计日期：2026-03-17  
> 审计目标：在数据库接入、首次对外提供服务前，梳理当前功能实现、上线阻塞项、可优化项、漏洞与欠缺。  
> 结论：**当前项目不建议直接进入正式上线。必须先完成 P0 安全与数据一致性整改，再进行数据库迁移与灰度验证。**

## 1. 审计范围与方法

| 维度         | 覆盖范围                                                               | 结论摘要                                                                     |
| ------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 产品功能     | 会话、语音、Realtime、收藏、复习、学习目标、成就、登录、文化卡片、翻译 | 主链路已形成 MVP，但部分模块仍是“开发期可演示状态”，未达到正式上线闭环       |
| 后端实现     | NestJS 控制器、Service、Prisma schema、缓存、AI 路由、鉴权             | 存在对象级越权、生产环境内存回退、迁移不完整等高风险问题                     |
| 前端实现     | React 页面、服务层、交互状态、构建                                     | 主要页面齐全，体验做得较细，但包体偏大、脚本可移植性不足、部分功能未真正接通 |
| 数据库准备度 | `schema.prisma`、迁移目录、运行期 DB 降级策略                          | schema 与迁移文件不一致，生产数据一致性风险高                                |
| 工程质量     | build / test / lint / 文档                                             | 单测通过，前端可构建；但 lint 未通过，文档基线不完整                         |

## 3. 与目标的对照结论

### 3.1 功能性目标

| 目标                      | 当前判断 | 说明                                                                          |
| ------------------------- | -------- | ----------------------------------------------------------------------------- |
| 有趣                      | 基本达到 | 语音、沉浸式、成就页、卡片复习带来一定趣味性                                  |
| AI 语音对话自然流畅不卡顿 | 部分达到 | 语音闭环已成型，且有 TTS 韵律与状态修复；但上线后仍缺并发、鉴权、异常压测验证 |
| 提供有效合理教学建议      | 基本达到 | Prompt 分层、评分、建议摘要已做，但仍需真实线上样本校验                       |
| 良好系统交互与学习小功能  | 基本达到 | 历史、摘要、收藏、复习、目标均有实现                                          |
| 良好单词复习机制          | 部分达到 | 有轻量间隔复习，但数据库与迁移不完整时会退回内存，不适合生产                  |
| 面向非母语者学习需求      | 基本达到 | 支持 native/target language 组合、翻译、提示、评分                            |
| 使用符合直觉              | 基本达到 | 会话页体验较成熟，但部分侧功能仍未完全闭环                                    |
| 前端 UI/UX 美观高级       | 基本达到 | 视觉风格统一，状态过渡也较细，但首屏包体偏大影响移动端加载体验                |

### 3.2 非功能性目标

| 目标                       | 当前判断       | 结论                                                               |
| -------------------------- | -------------- | ------------------------------------------------------------------ |
| AI 服务返回迅速不卡顿      | 部分达到       | 有主备模型、早广播、异步翻译，但缺线上限流、并发压测、超时治理指标 |
| 支持一定量并发             | 未验证         | 缺压测结论，且部分缓存/降级策略仍是单机内存模式                    |
| 易用性高                   | 基本达到       | 主要操作链路清晰                                                   |
| 可用性高                   | 未达到上线标准 | DB 不可用自动回退内存，会造成跨实例/重启数据丢失与不一致           |
| 良好安全性                 | 未达到上线标准 | 存在对象级越权、媒体访问控制缺失、开放 CORS/指标接口等问题         |
| 没有非一致性数据和 UI 显示 | 未达到上线标准 | 生产降级为内存、迁移缺失、SWR 缓存与服务端状态可能短时不一致       |

## 4. 上线阻塞项（P0）

| 级别 | 问题                                                     | 证据                                                                                                                                                                                                                                                                                                                                               | 风险                                                                                   | 建议                                                                                                                                               |
| ---- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0   | 会话与媒体接口存在对象级越权（BOLA）                     | `apps/server/src/modules/conversation/conversation.controller.ts:42,55,69,97,102,126`；`apps/server/src/modules/voice-tutor/voice-tutor.controller.ts:35,66,81,101`；`apps/server/src/modules/conversation/conversation.service.ts:318,331,355,1659` 只在“带 userId 且不一致”时拒绝                                                                | 已登录用户的会话、摘要、SSE、语音文件、TTS 结果可能被未授权访问或篡改                  | 所有会话/语音相关接口统一走 Guard 或在 Service 层使用 `session.userId && session.userId !== userId` 的硬拒绝规则；游客会话需要单独签名或临时 token |
| P0   | 收藏删除接口无鉴权且无所有权校验                         | `apps/server/src/modules/favorites/favorites.controller.ts:34`；`apps/server/src/modules/favorites/favorites.service.ts:114,118,130`                                                                                                                                                                                                               | 任何人只要知道 `favorite.id` 就可能删他人收藏                                          | 删除接口必须校验当前用户；DB 删除条件应改为 `where: { id, userId }` 或先查再删                                                                     |
| P0   | 数据库 schema 与迁移文件不一致                           | `apps/server/prisma/schema.prisma:100-195` 已声明 `ReviewQueueItem`、`ReviewFeedback`、`Achievement`、`UserAchievement`、`LevelDefinition`、`UserLevel`、`LearningGoal`、`LearningActivityDaily`；实际 migrations 只有 `20251116062241_init_db/migration.sql` 和 `202511270035_add_user_columns/migration.sql` 两个 SQL 文件，另外两个迁移目录为空 | 数据库上线后极易出现“代码引用表，但表不存在/字段不一致”的运行时错误                    | 先补齐正式迁移链，再在空库和已有库上各执行一次迁移验收                                                                                             |
| P0   | 生产环境 DB 不可用时自动回退内存，存在数据分裂与丢失风险 | `apps/server/src/core/prisma/prisma.service.ts:16,24,26,41,45`；`apps/server/src/common/cache/session-cache.service.ts:7,27`；`apps/server/src/common/cache/voice-operation-cache.service.ts:23,45`                                                                                                                                                | 一旦 DB 连接失败，服务仍“看似可用”，但数据写入只留在单机内存，重启或多实例后数据不一致 | 生产环境禁止静默回退为业务持久层；至少切为只读降级并明确返回错误                                                                                   |

## 5. 重要问题与欠缺（P1）

| 级别 | 问题                                             | 证据                                                                                                                                                                        | 影响                                                                       | 建议                                                                           |
| ---- | ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| P1   | 成就进度映射存在明显缺陷，且缺少授予写入闭环     | `apps/server/src/modules/achievement/achievement.service.ts:178,181,192` 用 `achievementId` 建 Map，再用 `def.code` 取值                                                    | DB 中已有成就进度时，前端仍可能拿到 0 进度；并且当前仓库未见成就授予写路径 | 用统一主键映射；补齐 conversation/review/focus 到 XP/achievement 的写入链路    |
| P1   | 翻译历史接口只返回内存数组，不读取数据库         | `apps/server/src/modules/translation/translation.controller.ts:14-16`；`apps/server/src/modules/translation/translation.service.ts:40,57`                                   | 服务重启后历史丢失，和 DB 已写入记录不一致                                 | `GET /translation/history` 应优先从 DB 读取，内存仅作短缓存                    |
| P1   | 文化卡片、翻译能力没有进入前端主流程             | 仓库中未发现 `apps/web/src` 对 `/culture`、`/translation` 的调用                                                                                                            | 已实现能力没有转化为用户可见价值                                           | 将文化卡片接入会话页或复习页；翻译入口与历史入口补到 UI                        |
| P1   | CORS 与监控暴露过宽                              | `apps/server/src/main.ts:20-21` 为 `origin: true` + `credentials: true`；`apps/server/src/modules/realtime/realtime.controller.ts:32-33` 暴露公开 metrics                   | 生产环境存在跨域与内部指标泄露面                                           | 白名单化前端域名；metrics 改为内网/鉴权访问                                    |
| P1   | Prisma schema 未定义索引，数据库规模上来后会退化 | `apps/server/prisma/schema.prisma` 未见 `@@index`；常用查询集中在 `Conversation.userId + updatedAt`、`ReviewQueueItem.userId + nextReviewAt`、`Favorite.userId + createdAt` | 首发后数据量一上来，历史、复习、收藏等查询会变慢                           | 为高频筛选和排序字段补联合索引                                                 |
| P1   | 工程脚本与质量门禁还未达到上线态                 | `apps/web/package.json:8` 使用 `tsc -b && vite build`；当前 `pnpm lint` 失败；`server` lint 还带 `--fix`                                                                    | CI/CD 在不同 shell 或严格门禁下不稳定                                      | 修正跨 shell 脚本；取消 lint 中的 `--fix`；把 lint/build/test 作为发布前硬门禁 |
| P1   | 前端首屏包体偏大                                 | `pnpm --filter web exec vite build` 结果显示主 chunk `assets/index-CWVPh4ft.js` 为 `980.10 kB`；`apps/web/src/App.tsx:3-8` 全量静态引入页面                                 | 移动端首屏加载压力大，影响“流畅不卡顿”目标                                 | 路由懒加载、拆分沉浸式与成就页、抽离大依赖                                     |

## 7. 上线前整改顺序

| 顺序 | 任务                       | 目标产出                                    | 通过标准                             |
| ---- | -------------------------- | ------------------------------------------- | ------------------------------------ |
| 1    | 收紧鉴权与对象访问控制     | 会话、语音、收藏接口全部按用户/游客凭证隔离 | 无法越权读取或写入他人资源           |
| 2    | 补齐 Prisma 迁移           | schema 与 migrations 完全一致               | 新库初始化成功，旧库迁移成功         |
| 3    | 取消生产静默内存回退       | 明确失败策略与降级边界                      | DB 故障不会写出“假成功”数据          |
| 4    | 补数据库索引与数据验证脚本 | 性能基线 + consistency checklist            | 历史/收藏/复习查询具备可接受响应时间 |
| 5    | 修正工程脚本与 CI 门禁     | shell 无关 build + lint/test/build 全绿     | 发布链路可自动执行                   |
| 6    | 补功能闭环                 | 成就授予、翻译历史、文化卡片入口            | 用户侧能真实感知能力价值             |

## 9. 结论

| 结论项                         | 判断                                                  |
| ------------------------------ | ----------------------------------------------------- |
| 是否已经可以“接数据库直接上线” | **否**                                                |
| 是否具备继续推进上线的基础     | **是**                                                |
| 最关键的 3 件事                | **先修越权、补齐迁移、关闭生产内存回退**              |
| 建议的推进方式                 | 先做一轮“上线加固 Sprint”，再上测试库和预发布环境验证 |
