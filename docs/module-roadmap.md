# LuvTALK 新功能模块路线与约束（v1）

> 更新日期：2026-03-08  
> 目标：把“接下来要做什么”从零散需求，升级为可追踪、可验收、可约束的模块化执行清单。

## 1. 使用规则

| 规则       | 说明                                                       |
| ---------- | ---------------------------------------------------------- |
| 模块准入   | 新功能必须先登记本文件，明确目标、边界、风险、验收后再开发 |
| 依赖顺序   | 安全与可用性模块优先于趣味与增长模块                       |
| 设计一致性 | 所有模块必须遵守“高级简约”UI 约束（见第 4 节）             |
| 指标闭环   | 每个模块至少绑定 1 个北极星指标与 2 个过程指标             |
| 灰度发布   | 默认先灰度（10%）再全量，除非为紧急漏洞修复                |

## 3. 模块详细约束

### 3.1 MOD-01 Trust & Access Shield

| 项目     | 约束                                                   |
| -------- | ------------------------------------------------------ |
| 目标     | 消除会话、收藏、SSE 等接口的越权访问风险               |
| API 约束 | 所有按 `id` 查询的私有资源必须显式做 `userId` 归属校验 |
| 安全约束 | 高成本接口必须有速率限制（IP + 用户双维度）            |
| 验收标准 | 未授权访问私有资源全部失败；限流命中后返回统一错误码   |

### 3.2 MOD-02 Reliability Core

| 项目     | 约束                                              |
| -------- | ------------------------------------------------- |
| 目标     | 避免“看起来在线但数据未持久化”的隐性故障          |
| 数据约束 | DB 断连后必须自动探活恢复，内存模式仅允许短时兜底 |
| 观测约束 | 会话 ID 贯穿日志，关键链路有耗时/失败率指标       |
| 验收标准 | 故障演练下可恢复，且不会产生永久数据分叉          |

### 3.3 MOD-03 First 45s Onboarding

| 项目     | 约束                                         |
| -------- | -------------------------------------------- |
| 目标     | 首次进入 45 秒内完成第一次开口               |
| 交互约束 | 引导步骤不超过 3 步，任何一步均可跳过        |
| 文案约束 | 单句不超过 18 汉字或 10 英文词，避免认知负担 |
| 验收标准 | 新用户首日 3 轮有效对话比例提升到目标值      |

### 3.4 MOD-04 Premium Minimal UI System

| 项目       | 约束                                                   |
| ---------- | ------------------------------------------------------ |
| 目标       | 建立统一且高质感的“高级简约”视觉系统                   |
| 视觉约束   | 统一 token：间距、圆角、边框透明度、阴影层级、字体阶梯 |
| 组件约束   | 复用优先，禁止同语义控件出现 2 套视觉风格              |
| 移动端约束 | 输入区永不被遮挡；悬浮组件必须避让底部安全区           |
| 验收标准   | 关键页面视觉一致性通过设计走查清单（>= 90%）           |

### 3.5 MOD-05/06/07（趣味与学习闭环）

| 模块              | 核心约束                                                 | 验收标准                   |
| ----------------- | -------------------------------------------------------- | -------------------------- |
| MOD-05 任务与连胜 | 激励必须绑定学习行为（开口、复习、纠错），禁止纯签到刷分 | 留存提升且复习达成率不下降 |
| MOD-06 学习周报   | 只展示可行动信息（进步/短板/建议），不做信息堆砌         | 周报打开率与继续练习率提升 |
| MOD-07 自适应训练 | 训练题只来源于真实低分错误，避免“泛题库”                 | 同类错误率连续 4 周下降    |

## 4. 高级简约 UI 统一约束（强制）

| 维度   | 约束内容                                  | 禁止项                      |
| ------ | ----------------------------------------- | --------------------------- |
| 结构   | 页面首屏只呈现关键任务信息，次级信息折叠  | 首屏堆叠 4 个以上并列功能卡 |
| 字体   | 统一标题/正文/注释三阶体系                | 同屏混用 4 种以上字号       |
| 颜色   | 中性底色 + 单一强调色策略（按场景可切换） | 多强调色并发导致视觉噪音    |
| 控件   | 主按钮、次按钮、弱按钮语义固定            | 同语义按钮样式频繁变化      |
| 动效   | 动效用于状态反馈与层级过渡                | 无意义循环动画或过度弹性    |
| 移动端 | 输入区与底部导航优先级最高                | 弹层/卡片遮挡输入与发送控件 |
