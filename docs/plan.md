# LuvTALK 下一阶段开发计划（v1）

> 目标：在不牺牲对话流畅度的前提下，让产品在 **稳定性、易用性、趣味性、学习效果** 四个维度都可量化提升。

## 0. 现状判断（基于当前仓库）

| 维度     | 当前基础                                                | 主要缺口                                             |
| -------- | ------------------------------------------------------- | ---------------------------------------------------- |
| 稳定性   | 已有 Realtime WS 代理、重连、缓存、SSE、游客/登录双路径 | 缺少统一观测指标、状态机约束、故障降级策略的验收闭环 |
| 易用性   | 三种聊天模式、历史会话、语音草稿、双语 UI               | 新手引导不足、失败提示可操作性弱、跨模式切换成本偏高 |
| 趣味性   | 成就系统、等级系统、词汇收藏、每日复习基础              | 缺少持续目标感（周目标/连胜）、玩法反馈弱            |
| 学习效果 | 评分、发音建议、key terms、review 队列                  | 缺少学习路径、可追踪结果指标、针对性训练闭环         |

## 1. 产品目标与量化指标（90 天）

| 目标分类 | 指标（KPI）                     | 当前问题                          | 目标值               |
| -------- | ------------------------------- | --------------------------------- | -------------------- |
| 稳定性   | Realtime 会话成功率             | 退出/切换边界场景容易出现残留连接 | >= 98%               |
| 稳定性   | 语音链路故障可恢复率（30s 内）  | 用户遇错后可恢复路径不明确        | >= 90%               |
| 易用性   | 新用户首日完成 3 轮有效对话比例 | 新手不知道怎么开口、何时切模式    | >= 70%               |
| 易用性   | 模式切换后 10s 内继续对话比例   | 模式跳转存在中断感                | >= 85%               |
| 趣味性   | 7 日留存（有学习行为）          | 成就有展示，缺行为驱动闭环        | +20%（相对当前基线） |
| 学习效果 | 每周有效复习完成率              | 复习入口弱、任务目标不清晰        | >= 60%               |
| 学习效果 | 用户“有用”反馈（4/5 分以上）    | 缺真实训练任务而非仅聊天          | >= 75%               |

## 2. 开发原则（本阶段）

| 原则     | 执行要求                                           |
| -------- | -------------------------------------------------- |
| 稳定优先 | 新功能必须先定义失败路径、重试策略、降级策略       |
| 数据先行 | 所有核心体验改动都要有埋点与可验证指标             |
| 学习闭环 | 每个“好玩”功能必须挂钩学习结果（词汇、口语、复习） |
| 渐进发布 | 先灰度，再全量；先 MVP，再增强                     |

## 3. 需求分层与优先级（Now / Next / Later）

| 优先级 | 主题     | 需求项                                                                                   | 验收标准                                                 |
| ------ | -------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| P0     | 稳定性   | 统一 Realtime 会话状态机（idle/connecting/connected/reconnecting/ended/error）与转移守卫 | 所有退出路径都能释放 WS、AudioContext、MediaStream、lock |
| P0     | 稳定性   | 增加会话级观测：连接耗时、失败码、重连次数、保存失败率                                   | 后台可按天查看错误 TopN 与成功率                         |
| P0     | 易用性   | 失败可恢复 UI（重连、回退文字模式、重试保存）标准化                                      | 任一错误都可一键继续对话或回退                           |
| P0     | 学习效果 | “学习目标”最小闭环：每日 10 分钟、每周 20 个词、3 次口语练习                             | 用户可设置目标并看到完成进度                             |
| P1     | 学习效果 | 错误驱动复习：从低分句子自动生成复习卡（语法/发音/表达）                                 | 每次对话后可生成至少 1 条可复习任务                      |
| P1     | 趣味性   | 连胜与任务系统（每日任务、周挑战）                                                       | 完成任务可获得 XP/徽章，且可回看学习收益                 |
| P1     | 易用性   | 新手引导（30 秒）与场景快捷开始                                                          | 新用户首次进入可在 1 分钟内完成首轮练习                  |
| P2     | 趣味性   | 好友挑战/同伴榜单（轻社交）                                                              | 可分享学习周报，不影响主链路性能                         |
| P2     | 学习效果 | CEFR/主题能力图谱                                                                        | 可视化展示“已掌握/待加强”能力点                          |

## 4. 里程碑计划（建议 4 个 Sprint）

| Sprint          | 目标             | 核心交付                                        | 风险点                     | 退出条件                   |
| --------------- | ---------------- | ----------------------------------------------- | -------------------------- | -------------------------- |
| S1（1-2 周）    | 把系统跑稳       | Realtime 状态机硬化、错误恢复统一、观测埋点上线 | 上游 API 不稳定导致误判    | 会话成功率达到基线并可观测 |
| S2（第 3-4 周） | 把体验做顺       | 新手引导、快捷场景、模式切换无缝化              | 交互改动影响老用户习惯     | 新用户首轮完成率明显提升   |
| S3（第 5-6 周） | 把学习闭环建起来 | 学习目标、错误驱动复习、练习总结页              | 复习数据质量不足           | 每周复习完成率达到目标     |
| S4（第 7-8 周） | 把产品变好玩     | 连胜、周挑战、奖励反馈和学习周报                | 激励过强导致“刷分”而非学习 | 留存提升且学习指标不下降   |

## 5. 具体需求拆解（可直接进开发）

### 5.1 稳定性（P0）

| 编号   | 需求                    | 技术方案                                | 验收方式                       |
| ------ | ----------------------- | --------------------------------------- | ------------------------------ |
| STB-01 | Realtime 生命周期一致性 | 前后端统一状态枚举与错误码映射表        | 编写 8 个关键路径集成用例      |
| STB-02 | 连接故障自动恢复        | 指数退避 1 次 + 明确回退到文字模式      | 弱网模拟下可恢复对话           |
| STB-03 | 资源释放防泄漏          | 退出/切模式/切会话统一走 teardown       | 浏览器性能面板无持续麦克风占用 |
| STB-04 | 观测告警                | 关键接口与 WS 增加结构化日志 + 统计面板 | 能定位“连接失败最高 3 原因”    |

### 5.2 易用性（P0/P1）

| 编号  | 需求           | 技术方案                                      | 验收方式                   |
| ----- | -------------- | --------------------------------------------- | -------------------------- |
| UX-01 | 新手 30 秒引导 | 首次进入弹出 3 步引导（选语言、选场景、开口） | 首次会话开始率提升         |
| UX-02 | 错误提示可操作 | Toast + CTA（重连/回退/重试）                 | 用户不需要刷新页面即可恢复 |
| UX-03 | 模式切换无损   | 切模式保留输入草稿与上下文状态                | 模式切换后继续率提升       |
| UX-04 | 学习路径入口   | 首页新增“今天该练什么”入口                    | 日活用户中入口点击率可统计 |

### 5.3 趣味性（P1/P2）

| 编号   | 需求         | 技术方案                             | 验收方式                   |
| ------ | ------------ | ------------------------------------ | -------------------------- |
| FUN-01 | 每日任务系统 | 三类任务：开口次数、复习数、连续天数 | 任务完成有即时反馈与奖励   |
| FUN-02 | 连胜机制     | 按“有效学习行为”计算连胜，不按纯登录 | 7 日连胜用户占比提升       |
| FUN-03 | 学习周报     | 自动生成“本周进步卡片”               | 可一键分享，不暴露隐私数据 |

### 5.4 学习效果（P0/P1/P2）

| 编号     | 需求         | 技术方案                                 | 验收方式                |
| -------- | ------------ | ---------------------------------------- | ----------------------- |
| LEARN-01 | 学习目标管理 | 用户设定日/周目标，系统自动追踪          | 目标达成率可统计        |
| LEARN-02 | 对话后总结   | 每次会话生成“做得好/待改进/下次建议”     | 用户可复用建议继续练习  |
| LEARN-03 | 错误驱动训练 | 从低分句子生成纠错练习（选择/跟读/改写） | 下次同类错误率下降      |
| LEARN-04 | 能力图谱     | 按语法/词汇/流利度维度展示趋势           | 至少 4 周可观察趋势曲线 |
