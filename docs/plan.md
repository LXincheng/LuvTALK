# LuvTALK 升级与治理执行计划（v2.0）

> 更新日期：2026-03-08  
> 核心结论：系统主链路可用，但在**访问控制、限流治理、数据一致性**上仍有高风险缺口。下一阶段按“先安全与可用、再体验与趣味、最终增长闭环”推进。

## 0. 本轮排查结论（漏洞与不足）

| 类别 | 发现 | 风险等级 | 证据（代码位置） | 影响 | 处理优先级 |
| --- | --- | --- | --- | --- | --- |
| 访问控制 | 会话详情接口可通过 `conversationId` 直接读取 | 高 | `apps/server/src/modules/conversation/conversation.controller.ts` (`GET :conversationId`) | 可能发生会话数据越权读取（IDOR） | P0 |
| 访问控制 | SSE 会话流接口未绑定用户权限 | 高 | `apps/server/src/modules/conversation/conversation.controller.ts` (`Sse :conversationId/events`) | 可能被未授权订阅会话更新 | P0 |
| 访问控制 | 收藏删除接口未校验资源归属 | 高 | `apps/server/src/modules/favorites/favorites.controller.ts` + `favorites.service.ts` (`DELETE :id`) | 知道 ID 可删除他人收藏 | P0 |
| 成本与滥用 | TTS/STT/Realtime 等高成本接口缺少统一限流 | 高 | `voice-tutor.controller.ts`、`realtime.controller.ts` | 易被刷接口导致成本失控或服务抖动 | P0 |
| 安全配置 | 全局 CORS 过宽（`origin: true` + `credentials: true`） | 中 | `apps/server/src/main.ts` | 增加跨站滥用面，策略不可控 | P0 |
| 安全配置 | `ValidationPipe` 未拒绝非白名单字段 | 中 | `apps/server/src/main.ts` | 输入污染风险与不可预期字段穿透 | P1 |
| 输入约束 | `SendMessageDto` 无长度上限 | 中 | `apps/server/src/modules/conversation/dto/send-message.dto.ts` | 超长输入可放大模型成本与响应延迟 | P1 |
| 运维稳定性 | DB 断连后降级内存且缺自动恢复策略 | 中 | `apps/server/src/core/prisma/prisma.service.ts` | 线上可能出现“可用但不持久”与数据分叉 | P1 |
| 可观测性 | 缺端到端 tracing 与业务告警分层 | 中 | 全局（日志已加但未成体系） | 故障定位慢，SLA 难保证 | P1 |
| 文档治理 | 缺失 `docs/goal.md` / `docs/architecture.md` / `docs/rules.md` | 中 | 文档目录现状 | 跨人协作约束不统一，易偏航 | P1 |

## 1. 下一阶段目标（90 天）

| 目标维度 | 指标（KPI） | 当前判断 | 90 天目标 |
| --- | --- | --- | --- |
| 安全性 | 高风险越权漏洞数量 | 存在多处 P0 | 归零（0 个未修复 P0） |
| 可用性 | 会话可用成功率（文字/语音/沉浸） | 有降级能力但观测不足 | >= 99.0% |
| 可恢复性 | 语音链路 30s 内恢复率 | 中等 | >= 92% |
| 易用性 | 新用户首日 3 轮有效对话完成率 | 偏低 | >= 75% |
| 易用性 | 关键任务完成时间（首次开口） | 偏长 | <= 45 秒 |
| 趣味性 | 7 日留存（有学习行为） | 玩法驱动弱 | +25%（相对基线） |
| 学习效果 | 每周复习达成率 | 中等偏低 | >= 65% |

## 2. 设计方向（高级简约）

| 设计轴 | 约束 | 落地要求 |
| --- | --- | --- |
| 信息密度 | 少而精、首屏只放核心信息 | 聊天页首屏最多 3 组重点控件，次要信息折叠/抽屉化 |
| 视觉语言 | 统一中性色玻璃态，不堆叠花哨效果 | 组件统一使用设计 token（圆角/阴影/边框透明度） |
| 排版系统 | 标题层级清晰、正文短句化 | 统一字号阶梯与字重，避免混用尺寸造成噪音 |
| 动效策略 | 动效服务反馈，不做装饰炫技 | 动效时长 160-280ms，避免连续弹跳/抖动 |
| 响应式 | 移动端优先，输入框永不被遮挡 | 所有悬浮卡片必须避让底部输入区与安全区 |
| 可访问性 | 对比度与状态提示可读 | 深浅主题均需通过基础对比度检查 |

## 3. 优先级与分层（Now / Next / Later）

| 优先级 | 主题 | 需求项 | 验收标准 |
| --- | --- | --- | --- |
| P0 | 安全 | 会话接口权限收敛（详情/SSE/历史） | 未登录仅能访问匿名会话；登录只能访问本人会话 |
| P0 | 安全 | 收藏删除增加归属校验 | 无权删除返回 404/403，补齐测试 |
| P0 | 稳定性 | 高成本接口统一限流（IP+User） | STT/TTS/Realtime 命中限流可控，系统无雪崩 |
| P0 | 稳定性 | CORS 白名单化 + 安全中间件 | 仅允许受信域名，默认安全头启用 |
| P1 | 可用性 | DB 断连自动探活恢复 | 数据库恢复后自动重连并恢复持久化 |
| P1 | 可观测 | 接口与会话链路 tracing + 告警 | 可按会话 ID 追踪全链路耗时与错误 |
| P1 | 易用性 | 首次体验 30 秒引导 + 快捷开口 | 新用户首轮完成率显著提升 |
| P1 | 体验 | 聊天信息架构精简（高级简约） | 关键路径点击减少，移动端无遮挡 |
| P2 | 趣味性 | 任务/连胜/周报激励闭环 | 激励提高留存且不牺牲学习质量 |
| P2 | 学习效果 | 错误驱动训练 + 能力图谱 | 同类错误率下降，4 周可见趋势 |

## 4. 里程碑（建议 4 个 Sprint）

| Sprint | 周期 | 目标 | 核心交付 | 退出条件 |
| --- | --- | --- | --- | --- |
| S1 | 第 1-2 周 | 漏洞封口 | 权限收敛、限流、CORS 白名单、安全头 | P0 漏洞关闭率 >= 90% |
| S2 | 第 3-4 周 | 稳态可观测 | 自动重连恢复、Tracing、告警看板 | 主链路 SLA 可量化 |
| S3 | 第 5-6 周 | 高级简约体验 | 聊天页 IA 重构、移动端控件避让、首启引导 | 首次开口时间 <= 45 秒 |
| S4 | 第 7-8 周 | 趣味与学习闭环 | 任务系统、周挑战、周报、复习强化 | 留存与复习率双提升 |

## 7. 文档与工程治理

| 项目 | 约束 |
| --- | --- |
| 文档基线 | 补齐 `docs/goal.md`、`docs/architecture.md`、`docs/rules.md`（本阶段必须） |
| 新模块追踪 | 新功能模块统一登记到 `docs/module-roadmap.md`，禁止口头需求直改 |
| 配置管理 | 新增环境变量必须同步 `.env.example` 与 `docs/deploy.md` |
| 验收机制 | 每个任务必须含“功能验收 + 回归用例 + 指标验证”三项 |

## 8. 非目标（本阶段不做）

| 项目 | 原因 |
| --- | --- |
| 多人语音房间 | 与当前单人学习主链路冲突，复杂度过高 |
| 重社交社区 | 当前应优先学习效果与稳态，不扩社交广度 |
| 自研模型训练 | 成本与周期过高，阶段目标不匹配 |
