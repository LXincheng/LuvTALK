# LuvTALK 开发一体化计划（v3.1）

> 更新日期：2026-03-17  
> 适用阶段：数据库接入与上线准备阶段  
> 核心目标：在保证安全性、数据一致性与可用性的前提下，完成数据库接入、上线前加固与发布门禁整理。

## 0. 开发阶段总原则（简化版）

| 原则     | 约束                                                | 落地方式                                                   |
| -------- | --------------------------------------------------- | ---------------------------------------------------------- |
| 环境一致 | 开发与部署使用同一套模型路由、Prompt 契约、接口行为 | 禁止仅在开发环境生效的业务分支逻辑                         |
| 安全可用 | 保留必要安全与容错，不引入复杂治理框架              | 仅保留输入校验、超时与回退、状态一致性、回归清单           |
| 删繁就简 | 不做多层开关矩阵、不做复杂灰度设计                  | 当前阶段不新增额外“回滚骨架”与复杂门禁流程                 |
| 小步迭代 | 每次改动可验证、可回归、可记录                      | 一次只推进 1-2 个核心任务，完成即更新 `plan.md` + `log.md` |

## 1. 最小安全与可用基线（必须满足）

| 链路       | 最小要求                         | 验收标准                                                |
| ---------- | -------------------------------- | ------------------------------------------------------- |
| 文本对话   | 请求参数合法、响应结构稳定       | 不出现空回复、字段缺失导致前端异常                      |
| 语音对话   | 录音上传、转写、回复、TTS 可闭环 | 不出现双气泡、残留 thinking、错乱中间态                 |
| 模型回退   | 主模型失败后按固定顺序回退       | `gpt-5.2` 失败后切 `deepseek-reasoner -> deepseek-chat` |
| 会话连续性 | 会话切换、历史恢复状态一致       | 不丢消息、不串会话、不会话闪烁                          |
| 学习闭环   | 收藏、复习、建议输出可用         | 建议可执行，格式稳定，不简化成空泛回复                  |
| 错误处理   | 超时和失败可解释、可恢复         | 用户可继续对话，不被阻塞在不可恢复状态                  |
