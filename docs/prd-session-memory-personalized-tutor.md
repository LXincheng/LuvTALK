# PRD：会话记忆与个性化语言导师增强（v1.1）

> 文档日期：2026-03-10  
> 更新日期：2026-03-10  
> 目标版本：`2026-Q2`  
> 范围：在不破坏现有稳定主链路前提下，提升“记忆能力 + 教学结构化 + 语音真实度 + 响应一致性”。

## 1. 背景与问题

| 维度       | 当前问题                                           | 用户体感                 |
| ---------- | -------------------------------------------------- | ------------------------ |
| 上下文记忆 | 跨轮次记忆弱，AI 对用户长期习惯与常错点利用不足    | “每轮像重新认识我”       |
| 教学结构   | 部分回复过短或缺少步骤化建议，尤其在 fallback 场景 | “能回复，但不够会教”     |
| 语音链路   | waiting 与回复到达存在时序错位风险，偶发中间态闪烁 | “状态条先没了，回复后到” |
| 个性化     | 发音/语法弱项画像未系统沉淀到后续教学策略          | “建议不够针对我”         |

## 2. 目标与非目标

### 2.1 目标

| 目标           | 量化指标（建议）                          |
| -------------- | ----------------------------------------- |
| 会话记忆可用   | 同会话内“重复问同信息”比例下降 40%        |
| 教学结构清晰   | 文本模式分点建议覆盖率 >= 95%             |
| 个性化纠错     | 用户高频错误命中率 >= 80%（近 20 轮统计） |
| 语音等待一致性 | loading 过早消失率 < 1%                   |
| 语音学习价值   | 发音建议被采纳后下一轮分数提升率 >= 25%   |

### 2.2 非目标

| 非目标                | 说明                                                  |
| --------------------- | ----------------------------------------------------- |
| 全局长期人格记忆      | 本期只做“会话级 + 用户学习画像级”，不做开放式人格记忆 |
| 引入重型向量数据库    | 本期先用结构化摘要与规则记忆，不强依赖新基础设施      |
| 改动现有核心 API 协议 | 以增量字段为主，保持兼容                              |

## 3. 关键用户故事

| 角色       | 用户故事                                                       | 成功标准                                |
| ---------- | -------------------------------------------------------------- | --------------------------------------- |
| 初学者     | 作为初学者，我希望 AI 记住我常犯错误，并给我下一步可执行建议   | 每轮至少 1-2 条明确步骤，建议可直接照做 |
| 语音学习者 | 作为语音用户，我希望系统能记住我的发音弱点并持续纠正           | 连续 3 轮同类发音建议一致且可执行       |
| 回访用户   | 作为回访用户，我希望 AI 延续我当前会话上下文而不是重复问同问题 | 会话上下文连续，避免重复澄清            |

## 4. 产品方案概览

## 4.1 记忆分层

| 层级             | 存储内容                                | 生命周期       | 用途           | 更新机制（切实可落地）                                                  |
| ---------------- | --------------------------------------- | -------------- | -------------- | ----------------------------------------------------------------------- |
| L1：短窗口记忆   | 最近 N 轮（建议 8-12 轮）关键 utterance | 会话内         | 保证对话连贯   | 同步：按轮次与 token 阈值滑窗裁剪                                       |
| L2：会话摘要记忆 | 当前会话目标、进度、已纠正点、未掌握点  | 会话内持续更新 | 防止回复漂移   | 异步：每 3-5 轮或归档时用“小模型提炼”更新；写入 `SessionMemorySnapshot` |
| L3：用户学习画像 | 高频错误、偏好语言、语速偏好、常用表达  | 跨会话         | 个性化教学策略 | 异步：从多轮对话提炼并合并；带权重/时间戳/掌握状态，支持衰退与覆写      |
| L4：语音表现画像 | 发音/节奏/语法维度趋势、近 7 天变化     | 跨会话         | 精准语音教学   | 异步：由 STT 结果 + 评分/建议聚合；按 7/30 天窗口衰退更新               |

> 关键原则：**主对话链路不做“同步提炼画像”**，避免首字延迟（TTFT）上升；画像与摘要更新必须走异步任务。

## 4.1.1 记忆流转与提炼触发（The "How"）

| 触发点             | 条件                              | 动作                                              | 使用模型建议                     | 产物                      |
| ------------------ | --------------------------------- | ------------------------------------------------- | -------------------------------- | ------------------------- |
| 同步写入（主链路） | 每次用户发言                      | 仅写入消息本体（不做总结）                        | 无                               | `Conversation.messages[]` |
| L2 摘要提炼        | 每 3-5 轮或 `archiveConversation` | 基于最近窗口提炼“目标/进度/纠错点/未掌握点”并合并 | `gpt-4o-mini` 或 `deepseek-chat` | `SessionMemorySnapshot`   |
| L3 画像更新        | L2 更新完成后、或每日低频合并     | 抽取高频错误/偏好与掌握状态，合并到画像           | `gpt-4o-mini` 或 `deepseek-chat` | `UserLearningProfile`     |
| L4 语音画像        | 语音消息完成并有 STT 文本         | 统计发音/节奏/语法维度趋势与常见问题              | `gpt-4o-mini` 或规则聚合         | `PronunciationTrend`      |
| 衰退/覆写          | 每次画像合并                      | 对久未出现的错误降权；对稳定提升项标记 mastered   | 无或小模型辅助                   | 画像字段权重更新          |

## 4.2 Prompt 注入策略（在调用外部模型前）

| 模块                | 注入内容               | 注入策略（成本可控）                              | 约束                   |
| ------------------- | ---------------------- | ------------------------------------------------- | ---------------------- |
| `response_contract` | 各模式输出契约与禁止项 | 永远注入（最短且稳定，利于缓存）                  | 违约自动补偿           |
| `memory_context`    | L1 + L2 结构化摘要     | 默认注入“短版”；超预算时只保留 L2                 | 长度上限，超长自动压缩 |
| `learner_profile`   | L3 学习画像            | 只注入“Top-K 高价值点”（如 3-5 条），其余按需检索 | 缺失则降级默认策略     |
| `voice_profile`     | L4 语音趋势            | 仅语音模式注入“近 7 天 Top-K”                     | 仅语音模式注入         |

## 4.2.1 动态检索与“按需技能”（Skills / Tools）

> 目标：避免随着用户长期使用导致 L3/L4 越来越大而“全量注入爆 token”，同时避免模型注意力被长尾信息稀释（lost-in-the-middle）。

| 技能（服务端能力/工具）                                | 输入                   | 输出                           | 触发规则（何时调用）                               | 备注                                          |
| ------------------------------------------------------ | ---------------------- | ------------------------------ | -------------------------------------------------- | --------------------------------------------- |
| `get_session_memory(conversationId)`                   | 会话 ID                | L2 摘要（短版/长版）           | 每次模型调用前（短版），或复习模式（长版）         | 由服务端直接注入，不依赖模型 function calling |
| `get_user_profile(userId, targetLanguage)`             | 用户 ID + 目标语言     | Top-K 画像点（错误/偏好/掌握） | 每次模型调用前注入 Top-K；其余不注入               | 画像点带 `lastSeenAt/weight/status`           |
| `get_user_error_book(userId, targetLanguage, limit)`   | 用户 ID + 语言 + limit | 长尾错题清单                   | 仅当触发“复盘/制定计划/用户追问进步”               | 允许返回较长内容，但按需                      |
| `get_voice_report(userId, targetLanguage, windowDays)` | 用户 ID + 语言 + 天数  | 语音趋势摘要                   | 仅语音模式、且当建议命中率下降或用户问“有没有进步” | 优先返回可执行建议，不返回大段数据            |

> 注：如果后续确认 Yunwu 主模型链路支持 function calling，可将上述技能开放为模型可调用工具；但 **v1 落地不依赖** 该能力，避免引入不确定性。

## 4.3 教学输出契约

| 模式      | 输出要求                           | 失败补偿                              |
| --------- | ---------------------------------- | ------------------------------------- |
| text      | 目标语言回复 + 母语 1-2 条分点建议 | 服务端自动补齐 `Study Steps/学习建议` |
| voice     | 自然短句 + 最多 2 条口语可执行建议 | 缺建议则服务端补齐最相关 1 条         |
| immersive | 极短推进式回复，低解释密度         | 超长自动裁剪                          |
| review    | 错因复盘 + 替代表达 + 1 条练习动作 | 缺练习动作则模板补齐                  |

## 4.4 上下文预算与截断策略（Context Optimization）

| 项目         | 策略                                                       | 目的                   |
| ------------ | ---------------------------------------------------------- | ---------------------- |
| 动态 L1 滑窗 | “轮次上限 + token 上限”双阈值；单轮超长输入先压缩再入窗    | 防止极端长输入撑爆窗口 |
| 历史优先级   | 优先保留：最近 2 轮完整对话 > L2 摘要 > L3 Top-K > 其余 L1 | 保证教学与连续性       |
| 注入总预算   | 语音/沉浸更小预算，文本/复习更大预算                       | 控制时延与成本         |
| 失败降级     | 超预算时：先丢 L1 冗余、再丢长尾画像、保留 L2 + 输出契约   | 保持稳定与一致性       |

## 5.5 提炼模型（异步 Summarization）选择

| 用途            | 优先模型                  | 备选模型            | 选择理由                       |
| --------------- | ------------------------- | ------------------- | ------------------------------ |
| L2/L3 信息抽取  | `gpt-4o-mini`             | `deepseek-chat`     | 成本低、速度快，适合异步批处理 |
| L4 语音画像聚合 | 规则聚合优先 + 小模型校正 | `gpt-4o-mini`       | 语音趋势可先用统计再用模型解释 |
| Judge/评测      | `gpt-5.2`（离线/批处理）  | `deepseek-reasoner` | 需要更强一致性与推理能力       |

## 6. 技术设计（可落地）

## 6.1 后端模块改造

| 模块                                 | 改造点                                                                                   | 是否影响主链路 TTFT    |
| ------------------------------------ | ---------------------------------------------------------------------------------------- | ---------------------- |
| `ConversationService`                | 增加 memory pack 组装（短版注入）；对话调用前按预算拼装上下文                            | 低（仅拼装，不做总结） |
| `Prompt Builder`                     | 增加 `response_contract/memory_context/learner_profile/voice_profile` 拼装顺序与预算截断 | 低                     |
| `Async Summarization Worker`（新增） | 异步提炼 L2/L3/L4：每 3-5 轮、归档、语音完成后触发；去重合并写库                         | 无（异步）             |
| `VoiceTutorService`                  | 输出语音维度统计事件（不在主链路等待）供 L4 聚合                                         | 低                     |
| `Normalizer`                         | 输出不合规时结构化补偿（契约兜底）                                                       | 低（纯字符串处理）     |

## 6.1.1 Prompt Caching 组装顺序（如果线路支持则命中缓存）

| 顺序 | 内容                           | 稳定性                  | 放置原因                       |
| ---- | ------------------------------ | ----------------------- | ------------------------------ |
| 1    | System 人设 + Output Contract  | 极稳定                  | 让缓存最大化，且保证契约不漂移 |
| 2    | L3 Top-K（短）+ 用户偏好（短） | 中稳定（低频更新）      | 头像画像通常跨轮复用，适合靠前 |
| 3    | L2 会话摘要（短）              | 中稳定（每 3-5 轮更新） | 比长历史更经济且抗漂移         |
| 4    | L1 最近对话（裁剪后）          | 高频变化                | 放尾部避免破坏缓存命中         |
| 5    | 本轮 user 输入                 | 高频变化                | 必须放最后                     |

> 注：即使线路不支持 Prompt caching，上述顺序也不会破坏正确性，主要收益是降低 token 与推理波动。

## 6.2 数据结构建议（增量）

| 表/结构                            | 字段（建议）                                                                                                 | 说明                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| `SessionMemorySnapshot`            | `conversationId`, `summaryShort`, `summaryLong`, `pendingGoals`, `lastCorrections`, `turnCount`, `updatedAt` | L2 会话摘要：短版用于每轮注入，长版用于 review |
| `UserLearningProfile`              | `userId`, `targetLanguage`, `preferences`, `errorItems`, `updatedAt`                                         | L3 画像建议存为结构化数组，支持衰退与覆写      |
| `UserLearningProfile.errorItems[]` | `key`, `title`, `examples`, `weight`, `count`, `lastSeenAt`, `status(active/mastered)`, `source(sessionId)`  | 记忆衰退/掌握标记的核心载体                    |
| `PronunciationTrend`               | `userId`, `targetLanguage`, `windowDays`, `scoreTrend`, `commonIssues`, `updatedAt`                          | L4 趋势按窗口存多份（7/30 天）                 |

## 6.2.1 记忆衰退与覆写（Memory Decay & Overwrite）

| 场景         | 规则                                                  | 目的                             |
| ------------ | ----------------------------------------------------- | -------------------------------- |
| 错误久未出现 | `weight` 按天/周指数衰退（例如每 7 天 \*0.85）        | 反映用户成长，避免旧错误长期干扰 |
| 连续正确     | 同类错误连续 N 次未出现则标记 `mastered`              | 让导师“划掉已掌握点”             |
| 模型误记     | 用户手动删除/纠正画像点，立即生效并写入 `preferences` | 保障可控与可信                   |

## 6.2.2 用户可控与隐私（遗忘权）

| 能力       | UI/交互                                   | 后端动作                                        |
| ---------- | ----------------------------------------- | ----------------------------------------------- |
| 可见记忆库 | “我的学习档案/AI 记忆库”页展示 Top 画像点 | 读取 `UserLearningProfile`/`PronunciationTrend` |
| 删除/纠正  | 支持删除某个画像点或标记“不再纠这个点”    | 更新 `status` 或移除记录，写审计字段            |
| 会话级忽略 | “本次对话不记录”开关（仅 L1）             | 本会话不触发异步提炼任务                        |

## 7. 开发落地计划（4 Sprint）

| Sprint | 周期   | 目标（可验收）          | 可交付（可直接落地）                                                                |
| ------ | ------ | ----------------------- | ----------------------------------------------------------------------------------- |
| S1     | 1-2 周 | L1/L2 可用且不拉高 TTFT | L1 滑窗裁剪（轮次+token）；L2 短摘要注入；超预算降级；埋点（TTFT/token/提前消失率） |
| S2     | 3-4 周 | L2/L3 异步提炼跑通      | 新增异步提炼 worker；每 3-5 轮/归档触发；画像结构化与衰退规则；不阻塞主链路         |
| S3     | 5-6 周 | 可见记忆库与按需检索    | “学习档案/记忆库”页；删除/纠正接口；按需获取长尾错题/语音报告                       |
| S4     | 7-8 周 | 可量化评测与灰度        | Golden Dataset（跨轮记忆）；LLM-as-a-judge 批量评分脚本；5%→30%→100% 灰度           |

## 8. 验收标准

| 类别      | 验收标准                                        |
| --------- | ----------------------------------------------- |
| 功能      | 会话记忆生效、分点建议稳定、语音状态一致        |
| 体验      | 无明显闪烁中间态，等待反馈连贯                  |
| 教学      | 建议具备可执行性，场景相关性显著提升            |
| 稳定      | 回退链路可用，主链路异常不阻断核心对话          |
| 成本/性能 | TTFT 无明显回退；token 超预算可降级且不破坏契约 |

## 8.1 评测基准（Evaluation）细化

| 项目           | 方法                                                  | 通过标准                   |
| -------------- | ----------------------------------------------------- | -------------------------- |
| 跨轮记忆正确性 | Golden Dataset：跨 10 轮问答（名字/口音/偏好/纠错点） | 命中率 >= 90%              |
| 结构化契约     | 规则检测：text 模式必须有 1-2 条分点建议              | 覆盖率 >= 95%              |
| 漂移与幻觉     | Judge 评审：是否编造用户信息、是否跑题                | 幻觉率 < 1%                |
| 成本与时延     | 采集 token 与 TTFT                                    | 相对基线可控（阈值按阶段） |

## 9. 风险与缓解

| 风险                    | 影响           | 缓解措施                                       |
| ----------------------- | -------------- | ---------------------------------------------- |
| Prompt 变更导致风格漂移 | 教学体验不稳定 | 强制输出契约 + 自动补偿 + 回归评测             |
| 回退模型输出过短        | 建议不可用     | DS fallback 结构化补偿与场景模板               |
| 状态机复杂度上升        | 中间态 bug     | 单一锚点清理策略 + 时序埋点 + E2E 回归         |
| 语音成本上升            | 运营成本压力   | 模型分层路由 + TTS/STT 策略开关                |
| 异步提炼堆积            | 延迟画像更新   | 去重合并、限频（每会话并发 1）、失败重试与降级 |
| 隐私与误记              | 信任受损       | 可见记忆库 + 删除/纠正 + 会话级不记录开关      |
