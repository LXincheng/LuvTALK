# LuvTALK 场景练习设计说明

> 更新时间：2026-04-02

## 1. 产品定位

`Chat` 是自由练习场，`Scenario` 是任务式训练链路。

场景页的目标只有三个：

| 目标 | 说明 |
| --- | --- |
| 进入快 | 选场景、选语言、马上开始，不堆说明文字 |
| 过程稳 | AI 固定角色、围绕任务推进、支持语音输入 |
| 反馈清 | 结束后给结构化评分和下一步建议 |

## 2. 当前范围

| 模块 | 当前方案 |
| --- | --- |
| 场景入口 | 独立一级入口 `/scenarios` |
| 开始前页 | 展示角色、目标、语言、预计时长 |
| 会话页 | 复用 `conversation` 基础设施，但保留场景头部与结束反馈 |
| 快捷胶囊 | 根据当前轮次、最近一条 AI 消息、最近一条用户消息动态生成 |
| 语音 | 支持录音，优先保证跨浏览器兼容 |
| 音色 | 不提供场景内音色切换，统一由官方推荐音色生成 |
| 反馈 | 结束时调用真实场景反馈接口，不再展示 mock 评分 |
| Prompt | 由统一 scenario 配置生成角色、目标、推进规则和报告重点 |

## 3. 设计原则

| 原则 | 落地方式 |
| --- | --- |
| 低耦合 | 场景定义、快捷引导、Prompt、页面组件分别维护 |
| 高内聚 | 场景相关逻辑集中在 `scenario` feature 和服务端 prompt/config |
| 少解释 | 页面不堆大段教学文案，重点放在“现在该说什么” |
| 真数据优先 | 不再保留 mock 回复、mock 评分、写死的开场文案 |
| 角色优先 | 导师先是场景角色，再是教学者，不做脱离场景的发散解释 |
| 目标语言纯净 | 尤其在英语练习中，消息气泡不再混入中文等非目标语言内容 |

## 4. 会话页规则

### 4.1 快捷胶囊

快捷胶囊不再写死为固定 starter，而是按当前对话状态生成：

| 状态 | 胶囊来源 |
| --- | --- |
| 首轮未开口 | 基于当前场景目标生成开场句 |
| AI 正在追问 | 生成“先回答，再补细节”类建议 |
| 已进入中段 | 生成“继续推进任务”类建议 |
| 接近收尾 | 生成确认、结束、复述类建议 |

### 4.1.1 Prompt 约束

场景模式的核心规则已经统一收进服务端 scenario 配置，重点是：

| 约束 | 当前要求 |
| --- | --- |
| 角色扮演 | AI 必须始终留在当前角色，不跳出场景讲课 |
| 任务推进 | 每一轮先回应当前信息，再推进下一步任务 |
| 防跑题 | 用户偏题时，从角色内部自然拉回，不切到泛聊 |
| 收尾条件 | 只有关键目标完成后，才自然进入确认或结束 |
| 教学位置 | 教学提示放在纠错与反馈字段，不把母语说明塞进主回复 |

### 4.2 音色策略

| 学习语言 | 默认音色 | 候选音色 |
| --- | --- | --- |
| 普通话 | `Serena` | `Serena` |
| 粤语 | `Kiki` | `Kiki`, `Rocky` |
| 英语 | `Ethan` | `Ethan` |

> 场景页不再开放音色切换，避免设置冗余，也避免用户选到错误语言音色。

### 4.3 语音策略

| 项目 | 当前要求 |
| --- | --- |
| 录音 | 前端统一 MIME 选择与能力检测 |
| 上传 | 当前不再在前端暴露文件上传入口，只保留录音主链路 |
| 识别 | STT 不强绑单一语言，兼容英语、普通话、粤语混说 |
| 回复 | Tutor 仍按当前练习语言输出 |

### 4.4 输入交互

| 交互 | 当前要求 |
| --- | --- |
| 选中图片 | 立即弹出简短 toast，并在输入区展示缩略图 |
| 预览区 | 只保留缩略图和清除操作，不放解释性小字 |
| 图片发送后 | 用户气泡保留图片预览，AI 结合图片内容生成回复 |

## 5. 报告与反馈

场景反馈不再只看尾部几句，而是尽量结合整段场景对话。

| 输入依据 | 当前要求 |
| --- | --- |
| 对话范围 | 使用整段场景 transcript，而不是只截最近几句 |
| 目标维度 | 结合场景目标、完成信号、角色推进情况进行分析 |
| 真实指标 | 参考真实轮次、目标语言使用、混说情况、系统纠错线索 |
| 建议输出 | 只给短而具体的下一步建议，避免空泛鼓励 |

## 6. Prompt 与配置

| 项目 | 当前原则 |
| --- | --- |
| Prompt 管理 | 统一放在服务端 `common/config/prompts`，不散落在组件里 |
| 场景定义 | 页面文案走 locale，场景结构走配置，角色/目标走 definition |
| 会话主链路 | `qwen3.5-plus -> qwen3.5-flash -> deepseek-chat` 严格串行回退 |
| 反馈链路 | 优先轻量、结构化、可快速返回 |

## 7. 验收标准

1. 进入场景后可以立即开始真实对话，不出现 mock 内容。
2. 录音、上传、转写、AI 回复、TTS 播放链路可闭环。
3. 快捷胶囊跟随当前轮次变化，不出现跨场景串词。
4. 英语练习时，消息气泡不再混出中文翻译或双语主回复。
5. 结束练习后展示基于整段场景对话的真实结构化反馈。
6. 场景页不暴露多余设置，尤其不再提供音色切换。

## 8. 后续边界

当前不做这些能力：

| 暂不处理 | 原因 |
| --- | --- |
| 场景内切换音色 | 会增加选择成本，且容易选错语言音色 |
| 多套复杂难度系统 | 先保证基础训练闭环稳定 |
| 独立场景后端模块 | 现阶段继续复用 `conversation` 基础设施，降低维护成本 |
